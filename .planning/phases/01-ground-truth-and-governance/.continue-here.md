# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each was discovered through actual failure this session.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: green-offline-suite-proves-nothing-about-live — `vitest.config.ts` excludes `**/*.live.test.ts`, so a green local run never executes the live suite — the structural mitigation is to run `pnpm vitest run --config vitest.live.config.ts` (or dispatch `nightly.yml` and read the conclusion) before claiming a source-touching change is verified.
- [ ] CONSTRAINT: worktrees-fork-from-origin-HEAD — Claude Code's `isolation="worktree"` forks from `origin/HEAD`, never live HEAD, and ignores `worktree.baseRef` — the structural mitigation is to assert `git rev-parse HEAD` equals `git rev-parse origin/master` immediately before any worktree dispatch, and push first if they differ.
- [ ] CONSTRAINT: two-document-lockfile-is-correct — `pnpm-lock.yaml` legitimately contains two YAML documents (document one is pnpm 12's `packageManagerDependencies` self-pin) — the structural mitigation is to run `pnpm install --frozen-lockfile` before AND after any lockfile edit; an agent already "repaired" this once and broke fresh installs.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| green-offline-suite-proves-nothing-about-live | `*.live.test.ts` is excluded from the default vitest profile. Plan 01-02's live test kept a stale corpus key through a 257-passing local suite and failed only in nightly CI, twice. | blocking | Run the live profile explicitly, or dispatch `nightly.yml` and read the conclusion, before calling a source-touching change verified. Never infer live health from the offline suite. |
| worktrees-fork-from-origin-HEAD | A worktree executor was dispatched while master was 33 commits ahead of an unpushed `origin/HEAD`. It forked from the stale base, found none of the files it was told to fix, and halted correctly on its base assertion. One wasted dispatch. | blocking | Assert `HEAD == origin/master` before dispatching; push first. `gsd-tools query worktree.base-check --mode harness-worktree --pick shouldDegrade` must return `false`. |
| two-document-lockfile-is-correct | An executor read the lockfile's two YAML documents as corruption and rewrote it as one, dropping pnpm's `packageManagerDependencies` self-pin. `--frozen-lockfile` then fails outright. | blocking | Treat the two-document structure as correct. Prove any lockfile change with `pnpm install --frozen-lockfile` before and after. An empirical result beats textual inspection. |
| data-shape-coupling-invisible-to-overlap-check | The intra-wave `files_modified` overlap check compares declared file paths only. Plan 01-03 re-keyed `_directive.json` from `CELEX#paragraph` to `CELEX#article@lang3`; plans 01-02 and 01-04 were written against the old shape in parallel. Three separate call sites broke at merge and were found one at a time. | advisory | When a wave contains a plan that changes the SHAPE of a shared data file, serialise it or dispatch its dependents afterwards. Declared paths do not capture shape coupling. |
| undeclared-shared-planning-artefacts | `.planning/WINDOWS.md` and `.planning/REQUIREMENTS.md` were edited by three plans that declared neither in `files_modified`. Both conflicted at merge, and git's auto-merge produced ledger entries sharing the same `id` twice — a silent corruption. | advisory | Expect append conflicts on the ledger and on requirements. After resolving, renumber ids by `recorded_at` and recompute the frontmatter counts. Never trust the auto-merged union. |
| over-supplying-context-to-an-independence-task | The orchestrator's dispatch prompt for 01-07 quoted two of 01-06's convention facts into an `upstream_context` block, partially contaminating a pass whose entire value is independence. The executor reported it rather than concealing it. | advisory | For a re-derivation or independent-review task, pass the plan and nothing that leaks the first pass's conclusions. Let the plan's own context section govern. |
| dispatch-isolation-json-mutates-state | Calling `gsd-tools query dispatch-isolation --json` as a diagnostic re-resolves AND re-persists the run-scoped sentinel, silently reverting a recorded #683 degrade and causing the isolation guard to reject the next dispatch. | advisory | Never call that verb for inspection. Read `.gsd/dispatch-isolation-sentinel.json` directly, or pass `--force-isolation` with the value you intend. |
| vitest-scans-live-worktrees | `.claude/worktrees/` holds full checkouts of other branches. Both vitest profiles were collecting every test twice and reporting a running agent's in-progress tree as a failure — it inflated a 15-failure/2-file result to 19/4. | advisory | Fixed in both configs via `**/.claude/worktrees/**`. If a local test count suddenly doubles, suspect this first. |
